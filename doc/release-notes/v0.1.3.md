# WPF XAML Live Preview v0.1.3 (미리보기 릴리스 · 보안 수정)

**보안 수정이 포함된 릴리스입니다. v0.1.0~v0.1.2 사용자는 업데이트를 권장합니다.** 설치 방법, 요구 사항은 [v0.1.0 릴리스 노트](https://github.com/PhulGrimLab/WPFXamlViewer_VSCode/releases/tag/v0.1.0)와 같습니다(Windows 10/11 x64, .NET 10 Desktop Runtime, VS Code 1.90 이상).

> **이 버전은 시험 단계(Pre-release)입니다.** 코드 서명이 없고, 신뢰한 폴더에서는 프로젝트의 빌드된 DLL을 불러와 사용자 코드를 실행합니다.

## 보안
- **신뢰하지 않은 폴더에서 `.xaml`을 미리보기만 해도 코드가 실행될 수 있던 문제**: `ObjectDataProvider`, `x:FactoryMethod`, 임의 형식의 `{x:Static}` 같은 XAML 선언만으로 임의 정적 메서드(파일 쓰기, 프로세스 시작 등)가 실행되었습니다. 이제 신뢰하지 않은 폴더에서는 WPF 형식과 기본 값 형식만 허용하고, 위 구성과 로컬 파일/네트워크 위치를 가리키는 `Source` 등을 오류(`UntrustedBlocked`)로 거부합니다. 폴더를 신뢰하면 이전처럼 그려집니다.
- **폴더 없이 `.xaml` 파일만 연 창에서 신뢰 확인 없이 프로젝트가 자동 빌드되거나 DLL이 로드될 수 있던 문제**: 프로젝트 코드 실행은 이제 Workspace Trust에 더해 XAML과 `.csproj`가 열린 워크스페이스 폴더 안에 있을 때만 허용합니다.
- 악의적인 입력으로 호스트가 종료되던 문제(줄바꿈이 CR뿐인 문서, 중복 키 JSON), 병합 사전 오류 메시지에 파일 내용 조각이 실리던 문제, 다른 창의 호스트 임시 폴더를 일부 지우던 문제, 신뢰 렌더의 앱 리소스가 남던 문제 등을 고쳤습니다. 자세한 내용은 CHANGELOG를 보세요.
- 릴리스 워크플로의 쓰기 권한 분리, 액션 SHA 고정, 태그가 `main`의 조상인지 검증을 추가했습니다.

## 수정
- 프로젝트를 다시 빌드(또는 솔루션 정리 후 자동 빌드)한 뒤 미리보기가 모두 `RenderFailed`로 실패하던 문제: 호스트가 새로 시작해 다시 그립니다.
- 자동 빌드 중 다른 XAML로 바꾸면 "빌드 중"에서 멈추던 문제, 빌드 대기 제한 시간 없음, 빌드 중복 실행을 고쳤습니다.

## 설치
`wpf-xaml-live-preview-0.1.3.vsix`와 `SHA256SUMS.txt`를 내려받아 체크섬을 확인한 뒤 `code --install-extension .\wpf-xaml-live-preview-0.1.3.vsix`로 설치합니다. 이 확장은 자동 업데이트되지 않으므로 기존 버전은 덮어써집니다. VS Code가 실행 중이면 먼저 종료하세요.

## 알려진 한계
- 신뢰하지 않은 폴더의 보호는 허용 목록 방식이지만 완전한 샌드박스는 아닙니다. 호스트는 여전히 일반 권한의 프로세스입니다. 출처를 모르는 저장소는 신뢰하지 마세요.
- Visual Studio가 없는 깨끗한 PC에서의 설치/첫 실행, 미리보기 화면의 마우스 조작은 아직 사람이 확인하지 못했습니다.
