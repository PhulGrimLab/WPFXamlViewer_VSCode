# WPF XAML Viewer 사용자 가이드

> 이 확장의 목적: **Visual Studio 없이 VS Code에서 .NET 10 SDK로 WPF 프로젝트를 개발**하면서, XAML 화면(UI)을
> 편집 중에 실제 WPF 렌더링 결과로 바로 확인하는 것. Windows 전용.

## 1. 무엇을 해 주고 무엇은 안 해 주나

| 하는 일 | 이 확장이 담당? |
|---|---|
| XAML 편집 중 **실제 WPF 렌더링 미리보기**(편집하면 자동 갱신) | **예** |
| XAML 오류를 줄/열과 함께 Problems 패널에 표시 | **예** |
| 미리보기 요소 클릭 → 해당 XAML 줄로 이동, 에디터 커서 → 요소 강조 | **예** |
| 프로젝트의 사용자 컨트롤/`App.xaml` 리소스/병합 사전을 반영한 렌더링 | **예**(조건은 5절) |
| 프로젝트 생성, 빌드, 실행, 디버깅 | 아니오 — `dotnet` CLI와 C# 확장(C# Dev Kit 또는 C#)을 쓴다(2절) |
| 도구 상자에서 컨트롤을 끌어다 놓는 **드래그 앤 드롭 디자이너**, 속성 창으로 값 편집 | **아니오(지원하지 않음)** — XAML을 직접 편집하고 미리보기로 확인한다 |
| XAML 자동 완성/IntelliSense | **아니오** — 다른 XAML 확장을 함께 쓰면 된다 |
| 애니메이션/비디오/실시간 데이터 바인딩 동작 | 아니오 — **정적인 한 장면**만 그린다 |

## 2. 개발 흐름 (처음부터 끝까지)

필요한 것: **.NET SDK 10**, **.NET 10 Desktop Runtime**(미리보기 호스트 실행용), VS Code, 이 확장. Visual Studio는 필요 없다.

1. 프로젝트 만들기: `dotnet new wpf -n MyApp -o MyApp --framework net10.0` 후 VS Code로 폴더를 연다.
2. `MainWindow.xaml`을 열고 명령 팔레트(`Ctrl+Shift+P`)에서 **WPF XAML: Open Preview** 를 실행한다. 에디터 옆에 미리보기가 열린다.
3. XAML을 편집한다. 300ms 동안 입력이 멈추면 자동으로 다시 그린다. 오류가 있으면 Problems 패널에 표시되고 미리보기는 마지막 정상 이미지를 유지한다.
4. 사용자 컨트롤(`local:MyControl`)을 실제로 그리려면 프로젝트를 한 번 **빌드**(`dotnet build`)하고 **폴더를 신뢰**한다(5절).
5. 앱 실행/디버그는 `dotnet run` 또는 C# 확장의 디버거(F5)를 쓴다. 코드(`.cs`)를 바꿨다면 다시 `dotnet build` 해야 미리보기의 사용자 컨트롤에 반영된다.

## 3. 명령

| 명령 ID | 명령 팔레트 이름 | 설명 |
|---|---|---|
| `wpfXamlViewer.openPreview` | WPF XAML: Open Preview | 활성 `.xaml` 파일을 에디터 옆 패널에 미리보기한다. `.xaml`이 아니면 안내만 한다. |

별도의 설정 항목은 없다.

## 4. 미리보기 화면

- **줌**: 툴바의 −/+, **맞춤**(창에 맞춤), **100%**. `Ctrl+마우스 휠`은 포인터 위치를 기준으로 확대/축소한다. 200% 이상은 픽셀을 그대로 키워 보여 준다.
- **이동(팬)**: 이미지를 마우스로 끌어 이동한다. 거의 움직이지 않고 떼면 클릭으로 취급한다.
- **배경**: 체크무늬(투명 확인) / 흰색 / 어둡게.
- **렌더 크기**: W/H 입력 후 **적용**. 비우거나 **자동**을 누르면 해제. 루트 요소에 `Width`/`Height`가 명시되어 있거나 `d:DesignWidth`/`d:DesignHeight`가 있으면 그것이 우선한다(우선순위: 루트 명시 → 디자인 크기 → 요청 크기 → 콘텐츠 크기).
- **클릭 → 코드**: 이미지에서 요소를 클릭하면 에디터 커서가 그 요소의 시작 태그로 이동하고 요소가 강조된다. 겹친 요소는 가장 안쪽/위에 그려진 것이 선택된다. 템플릿이 만든 내부 요소는 그 컨트롤로 취급된다.
- **코드 → 미리보기**: 에디터 커서를 옮기면 커서가 속한 가장 안쪽 요소가 강조된다.
- **상태 표시줄**: `렌더 중` / `XAML OK` / `XAML OK (경고 N)` / `XAML 오류`. 경고 위에 마우스를 올리면 목록이 보인다.

## 5. 사용자 컨트롤과 신뢰(Workspace Trust)

XAML에 프로젝트의 사용자 컨트롤(`xmlns:local="clr-namespace:MyApp"`)이 있으면 두 가지 방식으로 그린다.

| 방식 | 조건 | 결과 |
|---|---|---|
| **Tier 1 (실제 렌더)** | 폴더를 **신뢰**했고, 가장 가까운 `.csproj`의 `bin/**/<AssemblyName>.dll` 빌드 산출물이 있음 | 프로젝트 DLL을 불러와 컨트롤을 실제로 만들어 그린다 |
| **Tier 0 (자리표시자)** | 폴더를 신뢰하지 않았거나, 빌드 산출물이 없거나, 로드에 실패 | 사용자 컨트롤을 타입 이름이 적힌 붉은 박스로 표시하고 나머지는 정상 렌더 |

- 산출물이 여러 개(구성/TFM별)이면 **수정 시각이 가장 최신인 DLL**을 쓴다. 이 확장은 빌드하지 않는다.
- DLL은 임시 폴더로 복사해서 불러오므로 **원본이 잠기지 않는다**(미리보기 중에도 `dotnet build` 가능). DLL이 바뀌면 자동으로 다시 불러온다.
- 컨트롤 생성자가 예외를 던지면 그 컨트롤만 **주황색 오류 박스**(예외 요약)로 바뀌고 나머지는 그려진다.
- 컨트롤 안에서 `DesignerProperties.GetIsInDesignMode`로 분기하는 코드는 디자인 모드(`true`)로 동작한다.
- `App.xaml`의 `Application.Resources`(병합 사전 포함)가 문서의 리소스 아래 단계로 자동 적용되어 `{StaticResource}`가 풀린다.

### 보안 — 반드시 읽어 주세요
Tier 1은 프로젝트의 **사용자 코드(생성자 등)를 이 PC에서 그대로 실행**한다. 샌드박스는 없다. 그래서 **신뢰하는 폴더에서만** 켜진다
(VS Code의 Workspace Trust). 신뢰하지 않은 폴더에서는 사용자 코드를 절대 불러오지 않는다. 생성자에서 파일/네트워크/DB에 접근하는 컨트롤은
미리보기 때도 그 동작이 실행되며, 느리거나 그려지지 않을 수 있다. 요청이 제한 시간(기본 10초) 안에 끝나지 않으면 호스트를 강제 종료하고 다음 편집 때 다시 시작한다.

## 6. 문서 변환 규칙 (코드 비하인드 없이 그리기)

미리보기는 컴파일된 앱이 아니므로 다음과 같이 **읽기 전에 정리**한다. 바뀐 내용은 경고(상태 표시줄)로 알려 준다.

| 원본 | 처리 | 경고 코드 |
|---|---|---|
| `x:Class`, `x:Subclass`, `x:ClassModifier`, `x:FieldModifier` | 제거 | `RemovedClassAttribute` |
| `Click="..."` 같은 이벤트 핸들러 속성 | 제거 | `RemovedEventHandler` |
| `x:Code` 블록 | 제거 | `RemovedCodeBlock` |
| 해석할 수 없는 사용자 타입 | 자리표시자 박스 | `PlaceholderUsed` (+ 이유: `ProjectTier0`) |
| 사용자 컨트롤 생성 예외 | 오류 박스 | `UserControlFailed` |
| `ResourceDictionary Source="..."` | 파일을 읽어 인라인(없거나 순환이면 빈 사전) | `DictionaryUnavailable` |
| `Window` 루트 | 창 크롬 없이 콘텐츠만 `Width`/`Height` 크기로 그림 | — |
| `d:`/`mc:Ignorable` 디자인 타임 속성 | 그대로(런타임 값 사용, `d:DesignWidth/Height`는 크기에 반영) | — |
| 요소가 5,000개를 넘음 | 클릭 매핑을 5,000개로 제한 | `HitMapTruncated` |

오류 줄 번호는 항상 **원본 문서 기준**이다. 네트워크 URI(`http://...`)의 리소스는 읽지 않는다.

## 7. 제한 사항 (알려진 한계)

- **정적 렌더**: 로드 후 코드 비하인드(`InitializeComponent` 이후 로직, 이벤트 처리, 바인딩 DataContext 설정 등)는 실행되지 않는다. 바인딩은 값이 없는 상태로 그려진다.
- **창 크롬 없음**: `Window`의 제목 표시줄/테두리는 그리지 않는다. `SizeToContent`, `WindowStyle` 등 창 속성은 무시한다.
- **`{x:Type local:Foo}`, `{x:Static local:Foo.Bar}`, `TargetType="local:Foo"`** 처럼 요소가 아닌 자리에서 해석 불가 타입을 쓰면 자리표시자로 대체하지 못하고 오류가 난다. 신뢰된 폴더에서 DLL이 로드되면(Tier 1) 타입이 해석되므로 대부분 해결될 것으로 보지만 **시험해 보지 않았다.**
- 사용자 컨트롤 자리표시자(Tier 0)는 그 안의 자식 요소를 그리지 않는다.
- 크기가 0인 요소(빈 `Border`, `Collapsed`)는 클릭으로 선택할 수 없다. `Uid`를 직접 지정한 요소는 클릭 매핑에서 제외된다.
- 대상 프로젝트가 net8/net9여도 호스트(net10)에서 로드한다. 해당 TFM 전용 동작 차이는 시험하지 않았다.
- Windows 전용. x64.

## 8. 문제 해결

| 증상 | 원인/해결 |
|---|---|
| ".NET 10 Desktop Runtime이 설치되어 있지 않아 렌더 호스트를 시작할 수 없습니다" 알림 | .NET 10 **Desktop** Runtime(x64)을 설치한다. 알림의 `.NET 설치 페이지 열기` 버튼으로 이동할 수 있다. 확인: `dotnet --list-runtimes`에 `Microsoft.WindowsDesktop.App 10.x`가 있어야 한다. |
| "렌더 호스트(XamlRenderHost.exe)를 찾을 수 없습니다" | 설치된 확장에는 호스트가 들어 있다. 개발 중이라면 `dotnet build host/XamlRenderHost.slnx` 하거나 환경 변수 `XAMLVIEWER_HOST_EXE`에 exe 경로를 지정한다(지정하면 **그 경로만** 쓴다). |
| 사용자 컨트롤이 붉은 박스로 보임 | 상태 표시줄 경고의 `ProjectTier0` 이유를 본다: 폴더 미신뢰 → 신뢰, 산출물 없음 → `dotnet build`. |
| 사용자 컨트롤이 주황 박스로 보임 | 생성자 예외다. 경고 목록에 예외 요약이 있다. 생성자에서 디자인 모드를 고려하도록 고친다. |
| `{StaticResource X}` 오류 | 리소스가 `App.xaml` 또는 문서/병합 사전 안에 있어야 한다(코드 비하인드에서 추가하는 리소스는 볼 수 없다). |
| 화면이 갱신되지 않음 | Problems 패널과 출력 채널 **WPF XAML Viewer** 를 확인한다. 호스트가 죽으면 다음 편집에서 자동으로 다시 시작한다. |

## 9. 로그

- 확장 로그: VS Code 출력 패널의 **WPF XAML Viewer** 채널. 형식은 `[LEVEL] E0xx 메시지`.
- 호스트 로그: 확장의 전역 저장소 폴더 아래 `logs/host.log`(1MB × 5개 회전). `H0xx` ID로 기록되며 XAML 본문은 남기지 않는다.
- 주요 ID: `E010` 호스트 시작, `E011` 타임아웃(kill), `E012` 호스트 종료/실패, `H020` 사용자 DLL 로드, `H022` 사용자 컨트롤 예외, `H023` Tier 결정.
